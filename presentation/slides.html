03

Network design

CIDR plan that encodes tier & AZ

  • Public 10.0.1.0/24 · 10.0.2.0/24
  • App 10.0.11.0/24 · 10.0.12.0/24
  • Data 10.0.21.0/24 · 10.0.22.0/24
3rd octet = tier (1/11/21), last digit = AZ. Route tables and SG rules become self-documenting.
  • public-rt → Internet Gateway
  • app-rt → NAT Gateway (outbound only)
  • data-rt → local only, no internet route
/16 VPC + /24 subnets = room to grow. Avoids the “/28 too small” pitfall.
6 subnets · 2 AZs · IGW + 1 NAT
04

Security

Defense in depth, least privilege

Internet ─80/443─▶ ALB SG ─80─▶ App SG ─3306/5432─▶ Data SG
  • Internet reaches only the ALB — never an app or DB host
  • App accepts traffic only from the ALB SG
  • DB accepts traffic only from the App SG
  • Private tiers have no public IP
  • Data subnet has no internet route — protected twice
  • Admin via SSM — no SSH, no bastion, no port 22

08

Challenges & solutions

What broke, and how I fixed it

  • Blackholed NAT route — reused VPC pointed at a deleted NAT → created a new NAT + EIP, repaired the route
  • Data-tier isolation — all private subnets shared one route table → split data onto its own with no internet route
  • Testing private hosts — no SSH access → used SSM Session Manager / Run Command (no keys, no bastion)
  • Tooling gotcha — Git Bash rewrote /health into a path → fixed with MSYS_NO_PATHCONV=1
